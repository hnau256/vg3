# vg3 IR — формат моделей (v1)

Спецификация промежуточного представления (IR): **Kotlin-фронтенд → JSON → Rust-движок → STEP/STL**.

Односторонний поток: движок **только читает** JSON и **не сериализует** обратно. Сахар (шорткаты)
живёт в Kotlin-DSL и в JSON не попадает — канонический формат минимален.

---

## 0. Модель

- Единственная верхнеуровневая сущность — **`Part`**: OCCT `Compound`, состоящий **только из `Solid`**
  (0, 1 или больше тел).
- Любой узел возвращает `Part`. Конструкторы гарантируют solid (у `sweep`/`loft` торцы заливаются).
- Всё **безразмерное**; углы — **радианы**.

---

## 1. Верхний уровень

```json
{ "version": 1, "parts": [ <PartNode>, ... ] }
```

- `version` — целое; текущее значение `1`.
- `parts` — список узлов.

### Ссылки (operand)

Operand в любом месте — это либо **объект** (inline `PartNode`), либо **целое число** —
индекс **назад** в `parts`.

Правила:

- **Ссылаться можно только на индекс `< текущего`** — ацикличность гарантирована по построению.
  Отрицательный индекс или `>= parts.length` — ошибка.
- Промежуточные `Part` **не экспортируются**.

### Экспорт

Экспортируются **корневые** `Part` — те, на которые **никто не ссылается**.
Пустой результат (0 solid) — допустим. **Пустой `parts` — тоже валиден** (пустая модель, ничего не экспортируется).

---

## 2. Базовые типы и канонизация

Канонизация выполняется **при десериализации, в типах** (`try_from` из примитивов), **не проходом**.
После парсинга дерево всегда каноническое → ключ кэша канонический.

| Тип | JSON | Канонизация |
|---|---|---|
| `Scalar` | число (`f64`) | конечное; `−0 → +0` |
| `Angle` | число (`f64`) | конечное; `−0 → +0`; **не** приводится mod 2π |
| `Point2` | `{ "x": Scalar, "y": Scalar }` | компоненты — `Scalar` |
| `Point3` | `{ "x": Scalar, "y": Scalar, "z": Scalar }` | компоненты — `Scalar` |
| `Vector3` | `{ "dx": Scalar, "dy": Scalar, "dz": Scalar }` | компоненты — `Scalar`; **не нормируется** (сдвиг) |
| `Normal3` | `{ "dx": Scalar, "dy": Scalar, "dz": Scalar }` | **единичный**, знак **сохранён**; нулевой → ошибка |

Три «вида» значений: **Point** (позиция), **Vector** (сдвиг), **Normal** (единичное направление).
`Normal3` используется и для оси вращения, и для нормали зеркала.

> Для `rotate` знак оси важен, поэтому `Normal3` **не** канонизирует знак. Следствие: `mirror` с `n` и `−n`
> даёт разные формулы при одинаковом результате (избыточность кэша, не ошибка). При желании знак
> канонизируется локально в узле `mirror`.

> `Angle` **не** приводится mod 2π: иначе полный оборот (`revolve` на 2π) схлопнулся бы в 0. Следствие:
> `rotate` на `θ` и `θ + 2π` — разные ключи кэша при одинаковом результате (избыточность, не ошибка).

Сахар (`mirrorXY`, `rotateX`, `scaleX`, `circle`, `rect`, …) существует **только в DSL** и разворачивается
в канонические формы; в JSON он не встречается.

## 3. Геометрия

### Кривые (2D/3D — независимые типы)

```jsonc
// Curve2 (координаты Point2) / Curve3 (координаты Point3)
{ "type": "line",   "to":  Point }
{ "type": "arc",    "via": Point, "to": Point }   // дуга через 3 точки: start(=prev), via, to
{ "type": "spline", "points": [ Point, ... ] }    // интерполяция через точки

// Curve3 only — винтовая линия вокруг оси +Z через начало координат:
{ "type": "helix",  "pitch": Scalar, "height": Scalar, "right_handed": <bool> }  // default true
```

- `arc` и `spline` начинаются в конце предыдущего ребра (или в `start`).
- `helix` начинается в предыдущей точке (радиус и фаза берутся из неё): радиус = расстояние
  от оси +Z, высота и шаг задают число витков `height / pitch`.
- Нулевая длина ребра / самопересечение → ошибка.

### Контуры

```jsonc
Profile = { "start": Point2, "edges": [ Curve2... ] }   // 2D
Path    = { "start": Point3, "edges": [ Curve3... ] }   // 3D
```

- `start` обязателен.
- **`Profile` авто-замыкается всегда** (движок добавляет `line` last → start).
- **`Path` авто-замыкается только как секция `loft`**; в остальных случаях (спина `sweep`) — как задано.
- Профиль без рёбер / незамкнутый после авто-замыкания → ошибка.
- Круг выражается **двумя `arc`** (`circle` запрещён; в DSL — сахар `circle(...)`).

## 4. Операции

### 4.1 Примитивы (каноническая ориентация; размещение — только `transform`)

```jsonc
{ "type": "box",      "width": Scalar, "length": Scalar, "height": Scalar }  // угол в начале, +октант
{ "type": "sphere",   "radius": Scalar }                                     // центр в начале
{ "type": "cylinder", "radius": Scalar, "height": Scalar }                   // основание в начале, ось +Z
{ "type": "cone",     "radius_bottom": Scalar, "radius_top": Scalar, "height": Scalar } // ось +Z
{ "type": "torus",    "major_radius": Scalar, "minor_radius": Scalar }       // центр в начале, пл. XY
{ "type": "wedge",    "width": Scalar, "length": Scalar, "height": Scalar, "top_width": Scalar }
{ "type": "halfspace" }  // бесконечный solid z ≤ 0 (материал со стороны опорной точки); инструмент для cut
```

### 4.2 Генерация тел

```jsonc
{ "type": "extrude", "profile": Profile, "height": Scalar }   // из XY, вдоль +Z; height > 0
{ "type": "revolve", "profile": Profile, "angle": Angle }     // вокруг оси Y; профиль по одну сторону
{ "type": "sweep",   "profile": Profile, "path": Path, "mode": "follow" | "rigid" }  // default "follow"
{ "type": "loft",    "sections": [ Path, ... ], "ruled": <bool> }                    // default false, секций ≥2
```

- `revolve`: профиль не пересекает ось Y; иначе ошибка.
- `sweep`: профиль ставится в **начало спины, перпендикулярно касательной**.
  `mode`: `follow` — профиль поворачивается по спине (Frenet); `rigid` — жёсткий перенос.
  Вдоль спирали (`helix`) это даёт резьбу; ориентацию профиля в сечении задаёт движок
  (для `helix` вокруг +Z практически: X профиля — радиаль, Y — вдоль оси).
- `loft`: секции авто-замыкаются; проверяется совместимость (число/порядок рёбер).

### 4.3 Булевы

```jsonc
{ "type": "fuse",   "parts": [ operand, ... ] }                 // ≥ 1
{ "type": "cut",    "base": operand, "tools": [ operand, ... ] }
{ "type": "common", "parts": [ operand, ... ] }                 // ≥ 1
```

Ноль операндов → ошибка. Пустой результат (0 solid) — допустим.

### 4.4 Трансформации

```jsonc
{ "type": "transform", "target": operand, "ops": [ <Op>, ... ] }   // применяются слева-направо
```

```jsonc
{ "type": "translate", "value": Vector3 }
{ "type": "rotate",    "center": Point3, "axis": Normal3, "angle": Angle }
{ "type": "mirror",    "center": Point3, "normal": Normal3 }
{ "type": "scale",     "x": Scalar, "y": Scalar, "z": Scalar }     // НЕ Vector3
{ "type": "matrix",    "m": [ Scalar × 16 ] }                      // ROW-MAJOR 4×4
```

### 4.5 Fillet / chamfer

Один узел; структурно идентичны (`Add(value, edge)`).

```jsonc
{ "type": "fillet", "target": operand,
  "kind": "fillet" | "chamfer",                 // default "fillet"
  "radius":
      { "type": "all",        "radius": Scalar }
    | { "type": "expression", "expression": "<Rhai>" } }
```

- Движок обходит рёбра `target`; для каждого вычисляет значение; `≤ 0` → ребро пропускается.
- Для multi-solid `Part` применяется **к каждому solid'у**.
- **Seam-рёбра** (швы поверхностей — артефакт параметризации, напр. шов цилиндра) **не участвуют**:
  движок их не обходит (в выражениях они не видны) и не пытается скруглить (OCCT их не умеет).
- **Строгость**: любая ошибка (выражения, `Add`, непреодолимое ребро) → ошибка с контекстом.

---

## 5. Выражения (Rhai)

`expression` — исходник на Rhai; контекст — переменная `edge`:

| Свойство | Тип | Смысл |
|---|---|---|
| `edge.length` | `f64` | длина ребра |
| `edge.curve_type` | `string` | `"line"` \| `"arc"` \| `"spline"` |
| `edge.is_vertical` | `bool` | параллельно оси Z |
| `edge.is_horizontal` | `bool` | лежит в плоскости XY |
| `edge.direction` | `Normal3` | направление (для line) / касательная |
| `edge.radius` | `f64` | радиус дуги; иначе 0 |
| `edge.start` | `Point3` | начало |
| `edge.end` | `Point3` | конец |

- Результат — число; `≤ 0` → пропуск; не число / NaN → ошибка.
- Seam-рёбра в контекст `edge` не попадают (см. §4.5).
- **Строгость**: без тихих пропусков; ошибка содержит контекст (ребро, выражение, причина).
- Лимиты: `max_operations` (default **10 000**); IO-функции не регистрируются.
- Синтаксис — строго Rhai: тернарного `? :` нет, используйте `if cond { a } else { b }`.
- `edge.direction`, `edge.start`, `edge.end` — объекты с полями (`dx/dy/dz` и `x/y/z`).

## 6. Правила / неформализованное

- Ссылки — **только назад** (`index < current`); ацикличность гарантирована.
- Канонизация — **в типах** (`try_from`), не проходом; сахар — только в DSL.
- **Одна вещь — один способ** в каноническом формате.
- **Проверяем всё и падаем рано.** После каждой операции OCCT — `IsDone()` и валидность результата
  (`BRepCheck_Analyzer`); при проблеме — явная ошибка с контекстом, а не молча неверный шейп.
- Допуски не выставляются (OCCT-дефолты); параметры экспорта (формат, STL tolerance, размер PNG, …) —
  **в отдельном конфиге экспорта**, не в модели.
- Экспортируются корневые (неиспользуемые) `Part`.

---

## 7. Отложено (не в v1)

Дыры в профиле (`{outer, holes}`); символьные параметры (их нет — всё конкретно); hollowing (`shell`);
2D-offset профиля; зависимости через значения; instancing; импорт геометрии; цвета/имена/метаданные.

## 8. Пример

### Пластина с бобышкой, скруглённая по вертикальным рёбрам

Всё используется один раз → весь узел **одним деревом**, `parts` = один элемент:

```json
{
  "version": 1,
  "parts": [
    { "type": "fillet", "kind": "fillet",
      "target": {
        "type": "fuse",
        "parts": [
          { "type": "transform",
            "target": { "type": "box", "width": 20, "length": 20, "height": 5 },
            "ops": [ { "type": "translate", "value": { "dx": 0, "dy": 0, "dz": 5 } } ] },
          { "type": "cylinder", "radius": 5, "height": 10 }
        ]
      },
      "radius": { "type": "expression",
                  "expression": "if edge.is_vertical { 2.0 } else { 0.0 }" } }
  ]
}
```

### Переиспользование: шестерня

Зуб нужен N раз → **только он** выносится в `parts`; трансформы и тело — inline:

```json
{
  "version": 1,
  "parts": [
    { "type": "extrude", "profile": { "...зуб..." }, "height": 5 },

    { "type": "fuse", "parts": [
        { "type": "transform", "target": 0,
          "ops": [ { "type": "rotate", "center": { "x":0, "y":0, "z":0 },
                     "axis": { "dx":0, "dy":0, "dz":1 }, "angle": 0.0 } ] },
        { "type": "transform", "target": 0,
          "ops": [ { "type": "rotate", "center": { "x":0, "y":0, "z":0 },
                     "axis": { "dx":0, "dy":0, "dz":1 }, "angle": 0.2617993877991494 } ] },
        { "type": "cylinder", "radius": 20, "height": 5 }
      ] }
  ]
}
```

**Правило:** в `parts` попадает ровно то, что используется **> 1 раза** (переиспользование) — плюс
корни. Однократные узлы фронтенд вкладывает inline.
