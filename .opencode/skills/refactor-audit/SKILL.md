# Refactor audit

Ищет накопившиеся за итеративную разработку проблемы: копипасту, архитектурные компромиссы, лишние
слои/абстракции, костыли, мёртвый код, несогласованность. Сначала **только предлагает** исправления;
выполняет, коммитит и пушит — **после явного подтверждения** пользователя.

## Предусловия

1. Прочитай `AGENTS.md` — это критерий «правильно/нет» для всех находок.
2. Убедись, что дерево чистое (`git status`). Есть незакоммиченные изменения — остановись и сообщи.
3. До подтверждения ничего не меняй: фаза анализа — read-only.

## Что искать (категории)

Прогоняй по обеим частям — `processor/crates/*` (Rust) и `kt/` (Kotlin), плюс `README.md`/`AGENTS.md`.

- **A. Дублирование / копипаста.** Почти одинаковые блоки, параллельные реализации, повторяющиеся
  паттерны. Смотри повторы между `fillet.rs`/`fillet2d.rs`, `math2d.rs`/`math3d.rs`, `Arena`/`Lowering`,
  тестами, фикстурами, `SolidExt`/`RegionExt`.
- **B. Лишние слои / абстракции.** Обёртки, ничего не добавляющие; «умная» прослойка над OCCT;
  абстракции, не отражающие OCCT (AGENTS: «не добавлять абстракции, не отражающие OCCT»); лишние
  конверсии туда-обратно.
- **C. Нарушения слоёв.** `vg3-cache` не знает `Body`/`Part`; `expression.rs` — доменно-агностичен;
  `native/` — по функции на операцию OCCT и тонкий; `gen-schema` универсален, домен — в `gen-solid`.
- **D. Два способа для одного.** AGENTS: «Одно — одним способом». Дублирующиеся API/варианты,
  альтернативные пути к одному результату.
- **E. Костыли / обходы OCCT.** Сентинелы (`0xff`, `<= 0`, `map_or(0, …)`), инвертированные флаги,
  захардкоженные имена/значения, маскировка ненадёжности OCCT (AGENTS: «не костылить»).
- **F. Мёртвый код.** Неиспользуемые функции/ветки/поля, устаревшие комментарии (напр. ссылки на
  удалённый `FORMAT.md`), закомментированный код.
- **G. Несогласованность.** Разные имена/дефолты/обработка ошибок для одного и того же; типы не
  выражают инварианты; ошибки превращаются в «пустой результат».

Сиды (уже замечено по ходу разработки — проверь, актуально ли, и не считай их автоматически
проблемой): `defaultSource` в KSP-генераторе хардкодит `false`; `detail::kUnset = 0xff`;
`max_degree.map_or(0, …)`; `angle_value` со сентинелом `<= 0`; `profile_face` — тривиальная обёртка;
`math2d`/`math3d` дублируют хелперы; несколько итераций рефакторинга контекста выражений.

## Как искать

- Для обхода — `explore`/`task` (запускай параллельно), для точных паттернов — `grep`/`glob`.
- Греп-подсказки: `unwrap_or`, `expect(`, `0xff`, `map_or(`, `unsafe`, `TODO`, `FIXME`, `HACK`,
  `#[allow(`, совпадающие имена функций в разных модулях, длинные почти одинаковые блоки.
- **Проверяй факты.** Прежде чем назвать что-то дублем/мёртвым/нарушением слоя — открой код, проверь
  вызовы и экспорты. Не выдумывай проблемы: лучше меньше находок, но каждая реальная.

## Формат отчёта

Один пронумерованный список, сгруппированный по категориям, отсортированный по важности. На каждую
находку:

```
N. [Категория] Короткое название
   Где: file:line (и другие места, если это дубль)
   Почему: в чём проблема + какой принцип AGENTS нарушен
   Фикс: конкретное предлагаемое изменение
   Риск/объём: низкий/средний/высокий; примерный объём
```

В конце — явный вопрос, что исправлять. Используй инструмент `question` (multi-select) со списком
находок; пользователь отмечает нужные.

## Выполнение (после подтверждения)

Для **каждой** подтверждённой находки, по одной:

1. Внеси изменение по `AGENTS.md`, минимально и по существу.
2. Прогони проверки: `cd processor && cargo test -- --test-threads=1`; при изменениях Kotlin —
   `cd kt && ./gradlew :ktcad:build`; при изменениях модели — регенерируй схему (Gradle-таска).
   Пока не зелёно — не коммить.
3. Закоммить **только** файлы этой находки. Стиль сообщений — как в репозитории (`git log --oneline`):
   `type(scope): …`, ломающее — `type(scope)!: …`. Одна находка — один коммит.
4. Запушь (`git push`) в текущую ветку/remote.
5. Перейди к следующей подтверждённой находке.

Незаподтверждённые находки не трогай. Не смешивай несколько находок в один коммит.

## Остановка

- Находок нет — сообщи, что чисто.
- Находка не подтверждена — пропусти.
- Проверки не проходят или находка оказалась ложной — остановись на ней, доложи; не коммить.

## Запрещено

- Менять код до подтверждения.
- «Заодно» рефакторить то, чего нет в списке подтверждённых находок.
- Коммитить/пушить с красными проверками или посторонние файлы.
- Маскировать проблему (обход, сентинел, тихий `unwrap_or`) вместо устранения — по AGENTS.
- Коммитить несколько находок одним коммитом.
